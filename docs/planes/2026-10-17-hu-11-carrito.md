# Plan — HU-11 Carrito

Historia: `docs/historias/HU-11.md` · Issue #15 · Rama `feature/hu-11-carrito`

Backend: las líneas del carrito de cada Cliente en una tabla, una API
`/api/carrito` solo para el rol Cliente, y la respuesta siempre armada con el
precio y la disponibilidad de hoy, sin stock. Frontend: el botón en el
detalle, el ícono con número en el encabezado y la página `/carrito`.

## Tarea 2 — Servicio y API del carrito · backend

**Archivos:** `service/CarritoService.java`, `controller/CarritoController.java`,
`dto/CarritoResponse.java`, `dto/LineaCarritoResponse.java`,
`dto/LineaCarritoRequest.java`, `dto/CantidadRequest.java`,
`exception/ProductoAgotadoException.java`, `exception/CarritoLlenoException.java`
(nuevos); `config/SecurityConfig.java`, `service/InventarioService.java`.

- `CarritoResponse(List<LineaCarritoResponse> lineas, BigDecimal total, int
  cantidadLineas)`; `LineaCarritoResponse(idProducto, nombre, imagen, precio,
  unidad, cantidad, subtotal, estado)`, con `estado` `DISPONIBLE`,
  `AGOTADO`, `NO_DISPONIBLE` o `CANTIDAD_INVALIDA` y `subtotal` nulo fuera de
  `DISPONIBLE`. **Sin stock** (RF-14). El total suma solo las disponibles
  (RF-8, RF-9).
- `LineaCarritoRequest(@NotNull idProducto, @NotNull cantidad)` y
  `CantidadRequest(@NotNull cantidad)`: `cantidad` con `@DecimalMin(0,
  exclusive)`, `@DecimalMax(999)` y `@Digits(3, 2)` (RF-3); los decimales
  según la unidad los revisa el servicio con `InventarioService.admiteDecimales`
  y el mensaje sale de `mensajeDecimales` (mismo paquete: no cambian de
  visibilidad).
- `CarritoService` (`@Transactional`), **siempre con la fila del cliente
  bloqueada** (`UsuarioRepository.findConBloqueoByIdUsuario`): dos pestañas a
  la vez se aplican una después de la otra, sin perder una suma ni pasar de
  50 líneas (RF-2, RF-5, caso límite).
  - `ver(idUsuario)`: arma la respuesta con el producto de hoy.
  - `agregar(idUsuario, solicitud)`: el producto con
    `ProductoRepository.publico(id)` (inactivo, oculto o inexistente →
    `ProductoNoEncontradoException`, 404, igual en los tres casos, RF-4);
    agotado → `ProductoAgotadoException` (409, `PRODUCTO_AGOTADO`); si ya
    está, suma y revisa que el resultado no pase de 999 (RF-2, RF-3); si no
    está y hay 50 líneas → `CarritoLlenoException` (409, `CARRITO_LLENO`, RF-5).
  - `cambiarCantidad(idUsuario, idProducto, solicitud)`: la línea o 404;
    mismas reglas de cantidad (RF-10). Se puede cambiar aunque el producto
    esté agotado (para corregir una `CANTIDAD_INVALIDA`).
  - `quitar(idUsuario, idProducto)` (sin la línea, no hace nada) y
    `vaciar(idUsuario)` (RF-11).
- **Código completo de lo delicado** (bloqueo y transacción; `cambiarCantidad`,
  `quitar` y `vaciar` toman el mismo bloqueo primero):

  ```java
  static final int MAXIMO_LINEAS = 50;
  static final BigDecimal MAXIMO_CANTIDAD = new BigDecimal("999");

  @Transactional
  public CarritoResponse agregar(Long idUsuario, LineaCarritoRequest solicitud) {
  	// Con la fila del cliente bloqueada, dos agregados a la vez se aplican uno después del otro: ninguna suma se
  	// pierde y el límite de 50 líneas se cuenta sobre lo que dejó el anterior (RF-2, RF-5). La restricción única
  	// de la tabla queda como segunda defensa
  	Usuario cliente = usuarioRepository.findConBloqueoByIdUsuario(idUsuario)
  			.orElseThrow(UsuarioNoEncontradoException::new);
  	Producto producto = productoRepository.publico(solicitud.idProducto())
  			.orElseThrow(ProductoNoEncontradoException::new);
  	if (producto.getStock().signum() == 0) {
  		throw new ProductoAgotadoException();
  	}
  	Optional<LineaCarrito> existente = lineaRepository
  			.findByUsuario_IdUsuarioAndProducto_IdProducto(idUsuario, producto.getIdProducto());
  	BigDecimal cantidad = existente.map(linea -> linea.getCantidad().add(solicitud.cantidad()))
  			.orElse(solicitud.cantidad());
  	exigirCantidad(producto.getUnidad(), cantidad);
  	if (existente.isPresent()) {
  		existente.get().cambiar(cantidad);
  	} else {
  		if (lineaRepository.countByUsuario_IdUsuario(idUsuario) >= MAXIMO_LINEAS) {
  			throw new CarritoLlenoException();
  		}
  		lineaRepository.save(LineaCarrito.crear(cliente, producto, cantidad, LocalDateTime.now(clock)));
  	}
  	return ver(idUsuario);
  }

  // Los decimales según la unidad y el tope de la línea, también para el resultado de una suma (RF-3). Que sea
  // mayor que 0 y tenga hasta dos decimales ya lo validó la solicitud
  private static void exigirCantidad(UnidadVenta unidad, BigDecimal cantidad) {
  	if (!InventarioService.admiteDecimales(unidad, cantidad)) {
  		throw new CamposInvalidosException(
  				List.of(new CampoInvalido("cantidad", InventarioService.mensajeDecimales(unidad))));
  	}
  	if (cantidad.compareTo(MAXIMO_CANTIDAD) > 0) {
  		throw new CamposInvalidosException(List.of(new CampoInvalido("cantidad", "admite hasta 999")));
  	}
  }
  ```

## Decisiones del plan

- **Sin entidad `Carrito`:** las líneas cuelgan del usuario; una tabla menos y
  nada que crear al registrarse.
- **Bloqueo de la fila del cliente** en cada escritura, como el inventario
  bloquea la del producto: es lo que garantiza el límite de 50 y las sumas
  con dos pestañas.
- **Cada escritura devuelve el carrito entero:** la página y el ícono quedan
  al día sin otra petición.
- **El ícono solo para el Cliente:** el visitante no lo ve, porque abriría
  una página que pide sesión; agregar ya lo lleva a iniciar sesión.
