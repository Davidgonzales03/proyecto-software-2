# HU-14 — Mis pedidos

**Como** cliente, **quiero** ver mis pedidos y su estado, **para** hacer el seguimiento de mis compras y saber qué tengo pendiente de pago, pagado o entregado.

Issue: #18

## Contexto

El Cliente que realizó y confirmó pedidos (HU-12) y procesó su pago (HU-13) necesita
un punto centralizado donde consultar el historial de todas sus compras. En esta vista
puede identificar rápidamente qué pedidos están pendientes de pago, cuáles ya fueron
pagados y preparados para retiro, y cuáles finalizaron o vencieron.

Fuentes: issue #18; `CLAUDE.md` → «Usuarios y roles» (el Cliente compra y gestiona sus pedidos);
`docs/decisiones.md` → «Pedidos» (un solo pendiente por cliente, reserva y vigencia);
`frontend/src/app/app.routes.ts` (ruta `/mis-pedidos` reservada para este propósito).

Decisiones técnicas:
- **Endpoint backend:** `GET /api/pedidos` (retorna lista de pedidos del usuario autenticado
  ordenados de más reciente a más antiguo).
- **Ruta frontend:** `/mis-pedidos` protegida por `rolGuard` para el rol `CLIENTE`.
- **Aislamiento absoluto:** Un cliente solo accede a sus propios registros; las consultas
  filtran siempre por el `idUsuario` extraído del token JWT.
- **Sincronización de vencimiento:** Al solicitar la lista, se invoca `vencerSiCorresponde(idUsuario)`
  para asegurar que ningún pedido caducado aparezca como pendiente.
- **Acceso en cabecera:** La barra de navegación superior muestra «Mis pedidos» cuando la
  sesión pertenece a un usuario con rol `CLIENTE`.

## Requisitos funcionales (EARS)

- RF-1: CUANDO un Cliente autenticado consulta sus pedidos (`GET /api/pedidos`), EL SISTEMA
  devuelve la lista completa de sus pedidos ordenados de forma descendente por fecha de
  confirmación (el más reciente primero).
- RF-2: Para cada pedido de la lista, EL SISTEMA informa: número/identificador de pedido,
  fecha de confirmación, estado actual (`PENDIENTE_PAGO`, `PAGADO`, `ENTREGADO`, `CANCELADO`, `VENCIDO`),
  monto total en bolivianos (Bs.) y el desglose de productos con cantidades y subtotales.
- RF-3: SI un pedido se encuentra en estado `PENDIENTE_PAGO`, ENTONCES EL SISTEMA informa los
  segundos restantes para pagar y un acceso directo a la pantalla de pago (`/mis-pedidos/{idPedido}`).
- RF-4: CUANDO el Cliente selecciona un pedido de la lista, EL SISTEMA navega al detalle
  completo del pedido (`/mis-pedidos/{idPedido}`).
- RF-5: SI un usuario sin sesión activa intenta acceder a la lista de pedidos, ENTONCES EL
  SISTEMA responde 401 en la API y en el frontend redirige a la pantalla de inicio de sesión.
- RF-6: SI un usuario con rol distinto a `CLIENTE` (Administrador, Empleado, Contador)
  intenta acceder al endpoint `GET /api/pedidos`, ENTONCES EL SISTEMA responde 403.
- RF-7: EL SISTEMA nunca incluye en la respuesta pedidos pertenecientes a otros clientes.
- RF-8: SI el Cliente no registra ningún pedido previo, ENTONCES EL SISTEMA responde una
  lista vacía (HTTP 200 OK) y la interfaz muestra un estado vacío con enlace a «Explorar catálogo».
- RF-9: CUANDO se consulta la lista de pedidos, SI el Cliente tiene un pedido pendiente cuya
  hora de vigencia expiró, ENTONCES EL SISTEMA actualiza su estado a `VENCIDO` antes de retornar los datos.
- RF-10: MIENTRAS la sesión activa pertenezca a un `CLIENTE`, EL SISTEMA muestra el acceso
  «Mis pedidos» en la barra de navegación de la tienda.

## Escenarios

### Lista con pedidos (RF-1, RF-2, RF-4)
- **Dado** un cliente con dos pedidos: uno pagado por Bs 250 de ayer y uno pendiente de pago por Bs 80 de hoy
- **Cuando** abre «Mis pedidos» (`/mis-pedidos`)
- **Entonces** ve primero el pedido de hoy marcado como «Pendiente de pago» con tiempo para pagar, y luego el de ayer como «Pagado» con su total.
- **Y cuando** hace clic en «Ver detalle» del pedido pagado, la aplicación navega a `/mis-pedidos/{id}`.

### Cliente sin pedidos (RF-8)
- **Dado** un cliente recién registrado que no ha confirmado ninguna compra
- **Cuando** abre «Mis pedidos»
- **Entonces** ve el mensaje «Aún no tiene pedidos realizados» y el botón «Explorar catálogo» que lo lleva a `/catalogo`.

### Intento de acceso de otro rol (RF-6)
- **Dado** un usuario con rol `EMPLEADO` o `ADMINISTRADOR`
- **Cuando** intenta solicitar `GET /api/pedidos`
- **Entonces** el servidor responde 403 `Acceso denegado`.

### Vencimiento automático al listar (RF-9)
- **Dado** un pedido pendiente cuyos 30 minutos ya transcurrieron
- **Cuando** el cliente abre «Mis pedidos»
- **Entonces** el pedido se muestra con estado «Vencido» y el stock reservado queda liberado.
