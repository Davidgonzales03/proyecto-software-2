# HU-07 — Productos

**Como** administrador, **quiero** gestionar productos con precio,
descripción e imágenes, **para** venderlos.

Issue: #10

## Contexto

El Administrador da de alta los productos de la ferretería: nombre, código,
marca, categoría, unidad de venta, precio, descripción, una ficha técnica libre
y hasta cinco fotos. Un producto que ya no se vende se desactiva y no se borra,
para no perder el historial. El stock es de HU-08, el catálogo para los
clientes de HU-09 y el modelo 3D de HU-15. Esta historia también cierra lo que
quedó pendiente de HU-06.

Fuentes: issue #10; `CLAUDE.md` → «Usuarios y roles» (Administrador: todo lo de
la tienda) y «Tienda»; `docs/decisiones.md` → «Imágenes subidas», «Categorías
del catálogo», «Rubro: ferretería, con vista 3D» y «Sistema de diseño
(frontend)»; HU-06 (RF-8, RF-10 y RF-12 pendientes).

Decisiones de la entrevista (10/10/2026):

- **Datos:** nombre, código, marca, categoría (una sola, HU-06), unidad de
  venta, precio en bolivianos, descripción, ficha técnica e imágenes.
- **El código lo genera el sistema,** único, con el prefijo de la categoría en
  que se crea: las tres primeras letras sin tildes y en mayúsculas, un guion y
  el número del producto con cuatro cifras («JAR-0007»). No cambia si el
  producto pasa a otra categoría.
- **Unidad de venta de una lista fija:** unidad, metro, kilo, litro, caja,
  par, rollo.
- **Ficha técnica libre:** hasta 15 pares nombre–valor que el Administrador
  agrega, cambia o quita («Potencia: 750 W»), para los datos que cambian de
  una herramienta a otra sin tocar el sistema.
- **Hasta cinco imágenes; la primera es la principal** (la que muestra el
  catálogo). Se suben de a una, se reordenan y se quitan.
- **Un producto que ya no se vende se desactiva, nunca se borra:** inactivo no
  sale en el catálogo ni se puede comprar, pero queda para los pedidos y los
  reportes; se puede reactivar.
- Decididas con el proyecto, sin entrevista: el nombre **no** es único (dos
  «Martillo de uña» de marcas distintas son dos productos).

## Requisitos funcionales (EARS)

- RF-1: EL SISTEMA solo deja crear, editar, activar y desactivar productos, y
  cambiar sus imágenes, al Administrador: 403 a los demás roles, 401 sin
  sesión.
- RF-2: CUANDO el Administrador crea un producto con datos válidos, EL SISTEMA
  lo guarda activo, le asigna su código y lo muestra en la lista.
- RF-3: EL SISTEMA exige nombre (hasta 120 caracteres, sin ser solo
  espacios), categoría existente, unidad de la lista y precio mayor que 0 y
  hasta 99 999,99 Bs con dos decimales como máximo; la marca (hasta 60) y la
  descripción (hasta 1000) son opcionales; recorta los espacios alrededor.
- RF-4: EL SISTEMA genera el código con el prefijo de la categoría de alta y
  el número del producto («JAR-0007»), único, y no lo cambia después.
- RF-5: CUANDO el Administrador edita un producto, EL SISTEMA actualiza sus
  datos con las mismas reglas, incluida la categoría; el código no cambia.
- RF-6: EL SISTEMA guarda la ficha técnica como una lista ordenada de hasta 15
  pares, con nombre (hasta 40) y valor (hasta 100) obligatorios; un par vacío
  se descarta y dos con el mismo nombre se rechazan.
- RF-7: CUANDO el Administrador sube una imagen, EL SISTEMA la agrega al final
  con las reglas de «Imágenes subidas»; SI el producto ya tiene 5, ENTONCES la
  rechaza (409 `PRODUCTO_LLENO_DE_IMAGENES`).
- RF-8: CUANDO el Administrador reordena las imágenes o quita una, EL SISTEMA
  guarda el orden nuevo y borra el archivo quitado; la primera es la principal.
- RF-9: CUANDO el Administrador desactiva un producto, EL SISTEMA lo deja
  inactivo sin borrar nada; CUANDO lo activa, vuelve a estar activo.
- RF-10: CUANDO el Administrador abre «Productos», EL SISTEMA lista los
  productos de a 20, del más reciente al más antiguo, con código, nombre,
  categoría, precio, estado e imagen principal, y deja filtrar por categoría,
  por estado y buscar por nombre, código o marca.
- RF-11: SI el producto o la categoría no existen, ENTONCES EL SISTEMA responde
  404 (`PRODUCTO_NO_ENCONTRADO`, `CATEGORIA_NO_ENCONTRADA`).
- RF-12: CUANDO el Administrador intenta borrar una categoría con productos
  (activos o no), EL SISTEMA no la borra y responde 409
  `CATEGORIA_CON_PRODUCTOS`; la pantalla de categorías ofrece ocultarla.
  *(Cierra HU-06 RF-10.)*
- RF-13: EL SISTEMA muestra en la gestión de categorías cuántos productos tiene
  cada una. *(Cierra el conteo de HU-06 RF-12.)*

## Escenarios

### Da de alta un taladro (RF-2, RF-3, RF-4, RF-6)
- **Dado** la categoría «Herramientas eléctricas»
- **Cuando** el Administrador crea «Taladro percutor 750 W», marca Bosch,
  unidad «Unidad», 420,00 Bs, con la ficha «Potencia: 750 W» y «Mandril: 13 mm»
- **Entonces** aparece activo en la lista con el código «HER-0001» (o el número
  que le toque)

### Precio inválido (RF-3)
- **Dado** el formulario de producto
- **Cuando** pone 0 Bs, o 12,345 Bs
- **Entonces** se marca el precio y no se guarda

### Lo cambia de categoría (RF-5)
- **Dado** «Regadera metálica», código «HER-0003», en «Herramientas»
- **Cuando** la pasa a «Jardín»
- **Entonces** queda en «Jardín» con el mismo código «HER-0003»

### Fotos (RF-7, RF-8)
- **Dado** un producto con 2 fotos
- **Cuando** sube una tercera y la pasa al primer lugar
- **Entonces** esa es la principal; con 5 fotos, una sexta se rechaza

### Ya no se vende (RF-9)
- **Dado** un producto activo
- **Cuando** el Administrador lo desactiva
- **Entonces** figura como inactivo en la lista y se puede reactivar

### Busca (RF-10)
- **Dado** varios productos
- **Cuando** filtra «Jardín» y busca «bosch»
- **Entonces** ve solo los de Jardín con «bosch» en el nombre, el código o la
  marca

### Categoría con productos (RF-12, RF-13)
- **Dado** «Jardín» con 3 productos
- **Cuando** el Administrador intenta borrarla
- **Entonces** ve que tiene productos y se le ofrece ocultarla; la lista de
  categorías dice «3 productos»

## Casos límite

- **Precio con coma o punto** («420,5» o «420.5»): la pantalla acepta los dos;
  al backend viaja como número (RF-3).
- **Precio de exactamente 99 999,99:** se acepta; 100 000, no (RF-3).
- **Ficha con 16 pares o dos «Potencia»:** se rechaza indicando el motivo
  (RF-6).
- **Dos imágenes subidas a la vez al quinto lugar:** queda una sola; la otra
  recibe `PRODUCTO_LLENO_DE_IMAGENES` (RF-7).
- **Categoría inexistente** en la solicitud: 404 `CATEGORIA_NO_ENCONTRADA`
  (RF-11).
- **Categoría oculta:** se le pueden asignar productos (RF-3).
- **Borrar una categoría cuyo único producto está inactivo:** también se
  rechaza; el producto sigue existiendo (RF-12).
- **Reordenar con una lista que no coincide** con las imágenes del producto
  (de más, de menos o repetidas): se rechaza sin cambiar nada (RF-8).

## Fuera de alcance

- Stock y movimientos de inventario (HU-08).
- El catálogo público, la búsqueda del cliente y el detalle (HU-09, HU-10).
  Que los productos de una categoría oculta no se listen por ella (la parte
  pendiente de HU-06 RF-8) se prueba en HU-09, que es la que lista productos.
- Modelo 3D (HU-15).
- Ofertas, descuentos, variantes (tallas, colores) y precio por mayor.
- Importar productos desde un archivo.
- Borrar productos.
